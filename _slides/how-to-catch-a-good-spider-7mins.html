--- layout: slide title: | Catching a spider: Automating the Spider Algorithm in Complex Dynamics date: 2026-8-26 author: Wayne Peng coauthors: to: National Central University description: A seven-minute research talk on automating the Spider Algorithm using embedded graphs and path search. categories: academic abstract: | The Spider Algorithm is a well-known topological tool used to study the dynamics of polynomials and rational functions. However, implementing this algorithm computationally requires a system capable of distinguishing valid homotopic paths from tangled, intersecting ones. In this talk, we explore a computational framework that translates the continuous topological constraints of complex dynamics into discrete graph-theoretic algorithms. We will outline the process of generating discretized paths (spider legs) from a chosen base point to the post-critical set of a rational map, utilizing projective coordinates and the chordal metric to seamlessly handle limits at infinity. We then introduce an algorithmic method to evaluate the resulting monodromy graphs. By searching for vertex-disjoint paths and applying cyclic ordering, our algorithm programmatically verifies the existence of a "good spider" without human visual intervention. This provides a robust computational pipeline for exploring the Iterated Monodromy Groups of high-degree rational functions. tags: - research - academic - slides front-img: "/assets/img/slides/how-to-catch-a-good-spider/automata-1.png" ---

Let $\phi_c(x) = x^d + c$ and $\psi(x) = x^d$ be rational functions with $c\in\mathbb{Z}\setminus\{0\}$. Then we have

  1. $d$ even, $c>0$: $\sup_{x\in\mathbb{P}^1(\bar{\mathbb{Q}}\cap\mathbb{R})}||h_{\phi_c}(x)-h_{\psi}(x)|=|h_{\phi_c}(\pm 1)-h_{\psi}(\pm 1)|$
  2. otherwise: $\sup_{x\in\mathbb{P}^1(\bar{\mathbb{Q}\cap\mathbb{R})}|h_{\phi_c}(x)-h_{\psi}(x)|=|h_{\phi_c}(x_0 1)-h_{\psi}(x_0)|$ with $x_0$ a fixed point of $\phi_c$

Start with a simple dynamical system

Iteration means feeding the output of a function back into the same function.

For $f(x)=x^2-1$:

$$0\longmapsto -1\longmapsto 0\longmapsto -1\longmapsto\cdots\text{ and }\infty\to\infty$$

The critical points eventually repeat. Such a map is called post-critically finite, or PCF.

What can the infinitely many backward paths of this very simple system tell us?
0:40. Start with the idea of iteration, which requires no specialist background. In this example the critical orbit repeats. Say only that PCF maps have finitely many dynamically important points; do not give the formal definition unless someone asks.

Now run the process backward

Choose a point $t$. First solve $f(x)=t$, then solve $f^2(x)=t$, and continue.

$t \leftarrow f^{-1}(t) \leftarrow f^{-2}(t) \leftarrow \cdots$

The answers branch into a tree. The preimage of a loop from $t$ around a critical point is a path connect branches.

The iterated monodromy group records all of these shuffles. $$ \rho_f \colon \pi_1\!\left(\mathbb{P}^1(\mathbb{C})\setminus P_f,\,t\right) \longrightarrow \operatorname{Aut}(T_f), $$

0:40. A preimage is simply a possible previous value. Repeatedly solving backward creates a family-tree-like object. The iterated monodromy group is the symmetry group generated when the base point travels around the special points.

Why introduce a spider?

We need a consistent way to draw one loop around each special point.

Draw non-crossing paths from one common base point. Travel out along one leg, circle its endpoint, and return along the same leg.

This collection of legs is a spider.

0:40. The spider is just a coordinate system for loops. Each leg gives a standard route to one special point. These standard loops are enough to recover the symmetries of the preimage tree.

What is hard for a computer?

A person can often see when one path can be smoothly deformed into another.

Can a computer recognize the same path without continuously testing every possible deformation?
  • paths may bend, stretch, and look completely different;
  • they may not cross a special point or one another;
  • the method must also work near the point at infinity.
0:40. This is a homotopy problem: bending and stretching are allowed, but crossing a special point is not. Humans use the picture; a program needs finite data and an explicit certificate.

Key idea: replace the picture by a graph

Pull the spider backward through the function. The result is an embedded graph, which I call the web.

The web records only finite information:

  • which important points are connected;
  • which paths share a vertex;
  • the clockwise order of edges around each vertex.

The continuous deformation problem is now a finite graph-search problem.

0:45. This is the main idea of the talk. The web remembers connection and clockwise order, which are the parts of the picture that survive bending. Projective coordinates and the chordal metric let the construction treat infinity like any other point.

The algorithm

1
Approximate each spider leg by finitely many points
2
Pull back the legs and build the web
3
Search for paths that do not conflict
4
Check every local neighborhood and its clockwise order

Output: a finite certificate that the selected paths form a good spider.

0:50. Stress that each step is finite. The program samples the curves, lifts them, searches the graph, and verifies local order. Clockwise order distinguishes two drawings that have the same abstract connections but different topology in the plane.

When does the computer say “good”?

Sufficient checks

The selected paths pass if:

  1. they connect one chosen head to all required endpoints;
  2. they do not cross or compete for an interior vertex;
  3. the unused edge at each endpoint points to the correct special point;
  4. the clockwise order agrees with the original spider.

Passing these checks guarantees that the lifted loops can be recognized automatically.

0:50. These are sufficient checks, not a complete characterization of every possible good spider. The point is that a global deformation question is certified by path compatibility and local information in the web.
